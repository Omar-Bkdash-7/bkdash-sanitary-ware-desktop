# بكداش — نسخة سطح المكتب (ويندوز)

برنامج Flutter لحاسوب ويندوز، هو **نفس تطبيق الموبايل** (المخزون، الفواتير بـ PDF، الزبائن والديون، التقارير، القفل بـ PIN، النسخ الاحتياطي والتصدير، Telegram) بنفس الجداول الستة ونفس الخدمات. تُسجّل به فواتيرك وحساباتك على اللابتوب، وتنقل البيانات بينه وبين الهاتف عبر بوت Telegram.

> **حالة هذه النسخة:** كُتبت وفُحصت ثابتاً (انظر «التحقق») لكنها **لم تُترجم ولم تُشغَّل بعد على جهاز ويندوز**، لأن بيئة كتابتها لا تحوي Flutter. الخطوة الأولى عندك هي `tool\verify.ps1`؛ وأي خطأ يظهر فيها أرسله لي كما هو وأصلحه فوراً.

## كيف يتطابق مع الموبايل

* اسم الحزمة هنا `bkdash_sanitary_ware` كما في الموبايل، لذلك **110 من 118 ملفاً** في `lib/` (المخطط، المستودعات، PDF، Telegram، النسخ الاحتياطي، الشاشات…) تُنسخ من مشروع الموبايل **حرفياً** بسكربت واحد، فلا ينحرف جدول ولا استعلام بين الجهازين.
* ما كُتب خصيصاً لسطح المكتب قليل ومعزول: SQLite عبر FFI، المجلدات بدل MediaStore، لا بصمة، شريط جانبي، ومركز المزامنة.
* تفاصيل التصميم والقرارات: `docs/PLAN.md`. بروتوكول Telegram: `docs/SYNC_PROTOCOL.md`.

## المتطلبات

* ويندوز 10/11 (64 بت).
* Flutter بنفس إصدار مشروع الموبايل (3.47.x) مع تفعيل ويندوز: `flutter config --enable-windows-desktop`.
* Visual Studio 2022 مع حمل العمل **Desktop development with C++** (يتأكد منه `flutter doctor`).

## التشغيل لأول مرة

```powershell
cd bkdash_desktop

# 1) ولّد مجلد windows/ في مكان مؤقت وانسخه فقط (لا يمسّ lib ولا pubspec)
cd ..
flutter create --platforms=windows --project-name bkdash_sanitary_ware --org com.bkdash tmp_runner
Copy-Item -Recurse tmp_runner\windows .\bkdash_desktop\windows
Remove-Item -Recurse -Force tmp_runner
cd bkdash_desktop

# 2) (اختياري) اسم Bkdash.exe وأيقونة البرنامج
python tool\patch_windows_runner.py

# 3) التبعيات + تنسيق + تحليل + اختبارات
powershell -ExecutionPolicy Bypass -File tool\verify.ps1

# 4) التشغيل
flutter run -d windows
```

`verify.ps1` يشغّل `dart format` أولاً (ملفاتي كُتبت دون المنسّق، فقد يعدّل مسافات فقط)، ثم `flutter analyze --fatal-infos` ثم `flutter test`.

## أول استخدام

1. **أنشئ رمز PIN** (4 أرقام) عند أول فتح.
2. **اربط Telegram:** المزامنة ← «إعدادات تيليجرام»، وأدخل **رمز البوت ومعرّف المحادثة نفسيهما** المستعملين في تطبيق الهاتف، ثم «اختبار الاتصال».
3. **استورد بيانات الهاتف قبل تسجيل أي شيء هنا** (القسم التالي).

## الاستخدام اليومي: قاعدة التناوب

الاستيراد **يستبدل كل البيانات** بنسخة الملف (هكذا يعمل «استعادة» في الموبايل أيضاً)، ولا يوجد دمج. لذلك:

> **قبل أن تعمل على جهاز، استورد آخر نسخة من الجهاز الآخر. وبعد أن تنتهي، أرسل نسخة جهازك.**

| الاتجاه | ما يحدث |
|---|---|
| **كمبيوتر ← هاتف** | بعد كل فاتورة تصل الـ PDF إلى Telegram فوراً للمراجعة، وتُرسل نسخة قاعدة البيانات بعد 30 ثانية من آخر تعديل (ملف `bkdash_desktop_….db`). على الهاتف: احفظ الملف من Telegram ثم الإعدادات ← النسخ الاحتياطي ← «استعادة من ملف…». |
| **هاتف ← كمبيوتر** | الهاتف يرسل نسخته إلى Telegram بعد كل تعديل. في Telegram اضغط على آخر ملف `.db` من الهاتف ← **إعادة توجيه (Forward)** إلى محادثة البوت نفسه، ثم في المزامنة اضغط «جلب آخر نسخة من Telegram». أو احفظ الملف واختره بـ «اختيار ملف». |

قبل أي استيراد يعرض البرنامج **حكماً** بعد مقارنة السجلات في الجهازين:

* **آمن:** الكمبيوتر بلا بيانات بعد، أو الملف يحوي كل ما عندك وزيادة.
* **تحذير أحمر (لا يعمل زر الاستيراد إلا بعد إقرارك):** الملف **أقدم** من بياناتك، أو استُخدم **الجهازان** بعد آخر مزامنة (فاتورتان بالرقم نفسه). يُبيَّن كم سجلاً سيُحذف وكم سيُضاف.
* وفي كل الأحوال تُحفظ نسخة من بياناتك الحالية باسم `before_restore_…db` (النسخ الاحتياطي ← النسخ المحفوظة).

## أين الملفات؟

| ماذا | أين |
|---|---|
| قاعدة البيانات الحية وطابور Telegram | `%LOCALAPPDATA%\Bkdash\data` (محلي عمداً، فلا يلمسه OneDrive وهو مفتوح) |
| النسخ اليدوية و`before_restore_*` | `Documents\Bkdash\backups` |
| النسخ التلقائية (آخر 10) | `Documents\Bkdash\AutoBackups` |
| ملفات CSV والفواتير المحفوظة | `Documents\Bkdash\exports` |
| ما نُزّل من Telegram | `Documents\Bkdash\received` |

الإعدادات ← «فتح مجلد الملفات» يفتح `Documents\Bkdash`.

## اختصارات لوحة المفاتيح

`Ctrl+1` … `Ctrl+6` للأقسام (مخزون، فواتير، زبائن، تقارير، مزامنة، إعدادات) — `Ctrl+L` قفل البرنامج.

## التسليم (نسخة للمحل)

```powershell
flutter build windows --release
```

انسخ **كل** محتويات `build\windows\x64\runner\Release\` إلى اللابتوب (لا الـ exe وحده) وشغّل `Bkdash.exe` (أو `bkdash_sanitary_ware.exe` إن لم تشغّل `patch_windows_runner.py`). قد تعرض ويندوز تحذير SmartScreen لأن البرنامج غير موقَّع: «مزيد من المعلومات ← تشغيل على أي حال».

## إبقاء الكود مطابقاً للموبايل

كلما عدّلت الموبايل (جدول، استعلام، شاشة…):

```powershell
python tool\sync_from_mobile.py --mobile ..\bkdash_sanitary_ware --check   # هل هناك فرق؟
python tool\sync_from_mobile.py --mobile ..\bkdash_sanitary_ware           # انسخ
```

القواعد في `tool\shared_manifest.json` (ما يُنسخ، وما يُستبدل بنسخة سطح المكتب، وما يُتجاهل، ورقع نصية صغيرة مثل «الهاتف ← الجهاز»). إن أضفتَ ملفاً جديداً في الموبايل يتوقف السكربت ويطلب منك تصنيفه، حتى لا يُنسى شيء. **لا تعدّل الملفات المنسوخة في سطح المكتب** (ستُستبدل)؛ عدّلها في الموبايل أو انقلها إلى قائمة `override`.

## التحقق

| الأمر | ماذا يفحص |
|---|---|
| `tool\verify.ps1` | pub get، التنسيق، `flutter analyze`، `flutter test` (على ويندوز) |
| `python tool\check_project.py` | بنيوي بلا Flutter: الأقواس، الـ imports وترتيبها، غير المستخدم، معاملات المنشئات مقابل التعريفات الحقيقية، أعضاء `AppDependencies` |
| `python tool\validate_sync_logic.py` | يشغّل استعلامات المزامنة (مستخرجة من ملف Dart نفسه) على المخطط الحقيقي ويجرّب سيناريوهات الاستيراد |
| `python tool\sync_from_mobile.py … --check` | هل الملفات المشتركة ما زالت مطابقة للموبايل |

اختبارات `flutter test` الخاصة بسطح المكتب: المقارِن، تحليل التعليق، صندوق وارد البوت (خادم محلي يحاكي Telegram)، النسخ التلقائي، المسارات، القفل، **واختبار تكامل بقاعدتي SQLite حقيقيتين** (هاتف وكمبيوتر) يمر بمسار الاستيراد كاملاً. بالإضافة إلى 21 ملفاً من اختبارات الموبايل تعمل هنا كما هي.

## استكشاف الأخطاء

* **`Failed to load dynamic library 'sqlite3.dll'`** عند التشغيل: أضف المكتبة المضمَّنة بـ `flutter pub add sqlite3_flutter_libs` ثم أعد البناء؛ أو ضع `sqlite3.dll` (64 بت من sqlite.org) بجانب الـ exe. إن تعارضت إصدارات `sqlite3` عند `pub get` فاحذف السطر الذي أضفته وأرسل لي نص الخطأ.
* **«نسخة أخرى من بكداش مفتوحة»:** البرنامج يمنع نسختين على قاعدة واحدة. إن لم ترَ نافذة فأنهِ `Bkdash.exe` من مدير المهام.
* **Telegram 401:** رمز البوت خاطئ. **409:** للبوت webhook مفعّل أو برنامج آخر يسحب رسائله (مثل مستورد قديم)؛ أوقفه.
* **«جلب من Telegram» لا يجد شيئاً:** يجب أن **تعيد توجيه** الملف إلى محادثة البوت (ما يرسله البوت بنفسه لا يستطيع قراءته). الرسائل تبقى 24 ساعة عند Telegram، وبعدها أعد التوجيه.
* **حجم الملف > 20 ميغابايت:** حدّ Telegram لتنزيل البوتات؛ احفظ الملف يدوياً واستخدم «اختيار ملف».
* **لا أرى `Documents\Bkdash` في مكانه:** إن كان «المستندات» محوَّلاً إلى OneDrive فالمسار تحته؛ استعمل «فتح مجلد الملفات».

## حدود معروفة (بصراحة)

* **لا دمج بين جهازين:** رقم الفاتورة هو معرّفها التسلسلي وقد طُبع للزبون، فإعادة ترقيمها عند الدمج غير مقبولة. الحماية بالتناوب وبالحكم قبل الاستيراد، لا بالدمج.
* إن أغلقت البرنامج خلال 30 ثانية من آخر تعديل تنتظر نسخة قاعدة البيانات حتى التشغيل التالي (الـ PDF أُرسل فعلاً). اضغط «إرسال نسخة كاملة الآن» قبل الإغلاق إن كنت ستنتقل للهاتف فوراً.
* واجهات الموبايل منسوخة كما هي داخل شريط جانبي؛ تحسين تخطيطها لشاشة عريضة (جداول، لوحة مفاتيح في شاشة القفل، طباعة مباشرة، مثبّت) مؤجَّل — انظر `docs/PLAN.md`.
